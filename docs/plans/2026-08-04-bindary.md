# Mind2t - plan of record

> Written 2026-08-04 (IDT), approved by Orel the same night.
> **Engine keeps its name (`ruuah-vt`). The app is Mind2t** (born Bindary, briefly Sadna,
> renamed 2026-08-06). The "zero rebrand cost" this line used to claim was wrong twice over -
> the second rename touched 30 files, the crate directory, the GitHub repo and the config
> directory. Cheap, not free.
> Slice namespace is `B1..B9` and is DISTINCT from the `S1..S9` app slices in
> `APP-BACKLOG-2026.md`. Never mix them: S-numbers already have meanings and a
> session once rebuilt a shipped feature by reading a stale queue.

---

## 1. What Mind2t is

**An AGPL, cross-platform agent workbench with the best terminal engine in the category.**

You direct a fleet of coding-agent CLIs. They run in real terminals inside one window,
in git worktrees that make file ownership physically true, and their sessions do not end -
when a context window fills, the session is bound to the next one and the work continues.

The name: `bind` + `-ary`, the place-suffix of *library*, *granary*, *apiary*. The place
where binding happens. It also reads as *binary*, which for a terminal is free.

### The one-sentence differentiator

**We own the VT core, the pty, and the renderer. Nobody else in this category owns all three.**

| Product | Terminal | Consequence |
|---|---|---|
| BridgeSpace | rents xterm.js in a WebView | must render every byte to know what an agent is doing; ~10 of 26 releases are freeze fixes |
| Termic / Convoy | rents xterm.js in a WebView | same class, same ceiling |
| Claude Squad | rents tmux and your terminal | observation is `capture-pane` text you must regex |
| **Mind2t** | **owns `ruuah-vt`** | agent state comes from a **typed grid**, not from scraping ANSI |

`Session.rowText(row, semantic:)` already returns per-row OSC 133 semantic classes from the
last drawn frame. The sensor the competition approximates with regex is a function call here,
and it exists today.

### Why the freeze class cannot occur

BridgeSpace's entire backpressure saga - 256 KB drain budgets, single-write-in-flight gates,
stalled-callback watchdogs, a render scheduler shipped and rolled back twice - has one cause:
**bytes must reach a JS thread to be seen.** In Mind2t a 1 MB TUI repaint is parsed in Rust
off the UI thread and presented on the GPU at vsync. No terminal byte, no terminal pixel and
no pty-bound keystroke ever crosses into a webview. Those bugs are not fixed here; they are
unreachable.

## 2. Architecture

```
Tauri window
├── ONE wgpu surface        <- every terminal. Rust owns a split tree inside it.
│                              VT parse in Rust, render on GPU, present at vsync.
└── webview (React + TS)    <- tabs, sidebar, palette, diff panel, board, settings
```

**One surface, not one per pane.** The webview never learns how many panes exist. There is
exactly one native rectangle to position, size and DPI-track. Splits become Rust-side layout
arithmetic instead of DOM, which makes them *easier* than they would have been in Swift:
`ChromeLayout`'s EXACT TILING invariant (pane and sidebar sum to the content width, no overlap
and no gap) extends from two regions to a tree without changing its nature.

**The line this preserves**, already settled and not up for renegotiation:
xterm.js carries its own VT parser and screen model, so putting it in front of this core runs
two emulators and bypasses ours; blitting RGBA into a canvas is worse (12.5 MB a frame at
1120x700 @2x). **The terminal surface stays native. Only document-shaped panels get a browser
engine.**

### What already exists (verified 2026-08-04, `v0.19.3`)

| Layer | State |
|---|---|
| VT core, pty, frame, C ABI | done, gated: 605 tests / difftest 207/207 / esctest 373 pinned / exports 14+52 |
| Renderer, **CPU + GPU backends** | done. `Surface` is a 4-op trait; `tests/backend.rs` proves the wgpu backend **byte-identical** to the CPU reference, with a truncating control |
| Worktree workspaces + sidebar | done (S5, S5.5) |
| Shell integration, blocks, ghost history | done (S2, S4) |
| Palette | done (S3) |

| Swift host | 12 files, 4,479 lines - **becomes the oracle, not the target** |

### What is missing

Presenting to a screen. Splits. Agents. State. Context governor. Other platforms.

`gpu.rs` says it in its own header: *"NOT responsible for: presenting to a screen. This writes
into a storage buffer and reads it back; a window, a swapchain and a surface format are the
embedder's problem."* That sentence is the whole gap between here and B1.

## 3. The laws of this project

1. **The Swift host is the oracle, not the corpse.** Do not delete it. It is the only running
   proof the core works end to end. The Tauri host is ported to parity *against* it, then
   Swift is retired - the same discipline that makes the GPU backend trustworthy because a CPU
   reference exists to disagree with it.
2. **No terminal bytes in the webview.** Not pixels, not keystrokes, not frames. Ever.
3. **One surface.** Pane count is a Rust-side fact. If the webview needs to know it, the design
   is wrong.
4. **A checkpoint is falsifiable or it is not a checkpoint.** Every slice below states what must
   be SEEN, and the mutant that must be seen RED. "It looks right" closes nothing.
5. **Slow and surgical.** One slice at a time, gates green before the next starts, commit at
   verified seams. No slice may begin while the previous one has an open checkpoint.
6. **Aesthetics are Orel's verdict** (SCAR-014). Anything whose contract ends at the GUI is
   `[untested - needs your eyes]` until he looks.

## 4. The slices

### B1 - Present. `wgpu` swapchain from a raw window handle. **DONE 2026-08-04.**

**Closed with every checkpoint met.** Gate 610 tests / four smokes / 56 exports. Behind
`RUUAH_GPU_PRESENT=1`; the readback path is untouched and remains the oracle.

- byte equality: `tests/present.rs` requires the blitted frame to equal `read_pixels` byte for
  byte, and the assertion was **seen failing** under a red/blue mutant before being trusted.
- sRGB: refused at construction rather than compensated, both directions pinned.
- **zero readbacks**: the surface counts its own full-frame copies; presenting 30 frames must
  leave the count at 0, with a control proving the counter is not simply dead.
- live: window presents, follows a resize, and the margin wears the terminal's background.
  Before/after captures in `docs/images/b1-*-20260804.png`.

Four defects found on the way, three of them by Orel from screenshots, all silent by nature:
1. attach before layout gave a **1x1 swapchain** while the stale CGImage made the window look
   correct - which is why the attach report exists and why a failed present does NOT fall back;
2. the renderer rebuild minted a **new GPU device** every resize, orphaning the swapchain;
3. removing the readback also removed the **cell metrics** that gate `fitToPane`, so the grid
   silently never reflowed;
4. the margin was cleared to black instead of the terminal background.

The lesson worth carrying into B2: every one of these left a window that looked fine. Nothing
here can be judged by "it drew something".
**Goal.** The existing GPU backend draws into a real window instead of a readback buffer.
**Where.** `crates/render` gains a presenting surface; the **existing Swift host** hosts it.
No Tauri yet. This is deliberate: it isolates one variable.
**Checkpoint.**
- A live window rendered by the GPU path, screenshotted at native resolution, pixel-compared
  against the CPU path's frame for the same input. Byte equality is already the standard here.
- The sRGB control: a near-black fill must stay near-black. `gpu.rs` documents this trap
  (a surface format reporting `is_srgb()` interprets fills as linear and washes every colour
  out; paid for once already on 2026-05-18). A run with the wrong format must be seen washed out.
- No regression: 605 tests, difftest 207/207, esctest 373, five smokes still green.
**Risk.** Low. Contained to one crate with an existing oracle.
**Kills the project if it fails.** If a hosted `wgpu` surface cannot present cleanly, the whole
Tauri direction is dead - for two days instead of two months. **This is why B1 is first.**

### B2 - Tauri host, macOS only, parity with Swift.

**B2.1 DONE 2026-08-04** (`b24f3e9`): a wgpu surface presents in a `tao` window this project does
not own. New additive crate `crates/mind2t`, linking `ruuah-vt-host` as an rlib rather than
through the C ABI. Channel order and orientation pinned by an asymmetric fixture.

**B2.2 DONE 2026-08-04**: a TRANSPARENT `wry` webview composites over that surface, and input
routing is MEASURED rather than assumed. Deps: `wry 0.56` (+65 packages), `muda 0.19` (+5).

- **Z-order and transparency, one frame, three failure modes separated.** The page's marker
  overlaps the GPU pattern's green bar at 75% alpha: above the surface it tints the bar, below
  it the marker is absent, and an opaque page hides the bars entirely. Capture
  `docs/images/b22-webview-over-gpu-20260804.png`.
- **CREATION ORDER IS LOAD-BEARING.** wgpu creates the `CAMetalLayer` when the surface is
  created and AppKit stacks the newest sublayer on top, so the surface must exist BEFORE the
  webview subview. Reversed, the page ends up underneath and nothing errors -
  DioxusLabs/dioxus#3727 is that failure, open with no root cause. wry's own `examples/wgpu.rs`
  builds in the same order.
- **A full-window webview takes EVERY event.** ~150 gestures, zero on the native channel. The
  claim is only safe because the `bar` regime is its control: clipped to the chrome strip, the
  same build reported 29 native clicks with coordinates, so the window channel is alive.
  `MIND2T_OVERLAY=full|bar` keeps both regimes measurable.
- **A webview is clipped to its bounds** and draws nothing outside them
  (`docs/images/b22-overlay-bar-20260804.png`), so a chrome strip cannot cover the terminal by
  accident - only by being sized to.
- **cmd+A did nothing until an Edit menu existed**, and this is the slice's silent defect. AppKit
  routes an editing key equivalent through the main menu, so a WKWebView in an app with no menu
  RECEIVES the chord (`Meta`, then `a`/`KeyA` - it was in the log) and performs nothing. Same bug
  in webview/webview#99, electron#15219, vscode#129178. `install_menus` adds the app and Edit
  submenus; macOS reports `Select All` enabled. **The chord itself is still
  `[untested - needs your eyes]`** - it was not exercised after the fix.
- **Hebrew shortcuts must match `e.code`, never `e.key`.** Measured under the live layout:
  `{"key":"ש","code":"KeyA"}`. A chrome binding on `e.key` is dead under Hebrew by construction.
  This is SCAR-014's chord, caught before shipping instead of after.
- **WebKit runs macOS text substitution inside chrome inputs**: `that's` became `that’s` with no
  keystroke, and a lone letter was autocapitalised. Any real input needs it off.
- Operator feedback is drawn by the layer UNDER the webview: a native click marks the GPU
  surface where it landed (`docs/images/b22-native-click-marks-20260804.png`), which answers
  "did it arrive" and "is the page covering it" in one look, with no log to read.

**B2.5 DONE 2026-08-04**: the Tauri host reaches the PROBE's input parity - wheel, paste and the
child's working directory - and the gate grew from eight invariants to twelve by driving a real
child instead of only inspecting the window.

- **The wheel is an accumulator, not a rounding** (`crates/mind2t/src/wheel.rs`). A trackpad
  reports points and a terminal scrolls in rows, and most of a slow gesture's deltas are under
  one row; rounded individually every one of them is zero, so the viewport does not move while
  the gesture is plainly happening. The remainder is carried between events. Three of its five
  unit tests fail against the naive per-event rounding - that is the mutant, and it was run.
- **cmd+V is the ONE command chord the terminal claims**, and it has to be: the Edit menu's
  Paste reaches the FIRST RESPONDER, and the terminal is a GPU layer with none, so the chord
  does nothing at all unless the host performs it. Matched on the KEYCODE - under the Hebrew
  layout cmd+V carries `ה`, so a match on the character is dead by construction (B2.2's `e.code`
  finding, one layer down).
- **OSC 7 is decoded ONCE**, in `Session::take_events`, through `cwd::normalize` - the same
  decoder the C ABI's `ruuah_cwd_path` uses. Draining is not optional: the core's event queue is
  bounded at 128 and drops its OLDEST entry, so a host that never drains loses the beginning of
  every session silently.
- **Two shell facts the gate had to be redesigned around**, each of which made correct code look
  broken: zsh re-reports its own directory from `precmd`, so a synthetic report is overwritten
  milliseconds after the command ends (reading the value at the end of a run finds the
  repository - correctly and uselessly); and a returning prompt changes the grid with NO input,
  which breaks the stillness control of the scroll check. Both are handled by holding the child
  inside a long `sleep` and by recording the SEQUENCE of directories rather than the last one.
- **The gate never synthesizes input.** It drives `Session` directly, so it stays runnable while
  the operator works. The AppKit half - event mask, chord match, pointer-versus-strip test - is
  therefore a LIVE TAP, named rather than claimed.
- Each new invariant was seen red by its own mutant: the drain removed kills both directory
  checks, a paste that encodes and does not send kills the paste check, and a `Host::scroll` that
  accumulates nothing kills the wheel check - one each, no collateral.

**B2.6 DONE 2026-08-04**: mouse REPORTING - clicks, drags, motion and the wheel reaching a child
that asked for them - which was wired in NEITHER host before this, so the probe was no help and
the C ABI was the only reference. The gate is fourteen invariants.

- **One policy, not two.** The encoder is pure and oracle-measured, but the state around it -
  held buttons, the motion-dedup cell, view geometry - lived only inside the C ABI.
  `crates/host/src/pointer.rs` now holds it and BOTH surfaces call it. The five end-to-end mouse
  tests in `tests/host_abi.rs` predate the extraction and are what proves it changed nothing;
  had they not existed, the extraction would have been a rewrite with a hope attached.
- **The wheel has one destination**, chosen in this order: a report if the child captured the
  mouse, arrow keys on the alternate screen under mode 1007, otherwise the host's viewport.
  `Session::wheel` returns `Ok(false)` for the last case instead of scrolling, so no caller can
  act twice - scrolling the view under a full-screen program looks like a rendering bug.
- **A release is forwarded even from over the chrome strip**, unlike a press. The held-button
  bookkeeping is on the far side of that call, and a swallowed release leaves a button held
  forever, which the next motion reports as a drag nobody is performing.
- **`acceptsMouseMovedEvents` is NO by default**, so mode 1003 would have been silently half
  working: clicks and drags fine, bare motion never delivered.
- The gate's mouse check is TWO-DIRECTIONAL by construction - a click before the child enables
  reporting must be the host's, one after must be the child's - because a host that encodes
  unconditionally and a host with no mouse at all each satisfy one half. Mutants confirmed
  exactly that: the dead-mouse mutant kills both checks, the encode-always mutant kills only the
  two-directional one.

**Still not at Swift parity.** The palette, tabs, sidebar, blocks and diff panel are Swift-only.

**Goal.** A Tauri 2 window that hosts the B1 surface and reaches feature parity with the Swift
host: session spawn, keys, mouse, resize, scroll, palette, tabs, sidebar, blocks, diff panel.
**Checkpoint.**
- Every existing smoke (base, worktree, dock, panel, panel-control) passes against the Tauri
  host, not only against Swift.
- A live tap per input class, **including the Hebrew layout** and IME: the chord that died in
  SCAR-014 must be driven and seen working. Keys land in a webview first here and must be
  forwarded - this is the single most likely place to lose fidelity.
- Swift and Tauri hosts fed the identical corpus produce identical frames.
**Risk.** HIGH, and it is the port's real cost: z-order, resize sync, DPI, focus and event
routing between a webview and a native surface.
**Does NOT include.** Windows, Linux, splits, agents.

### B3 - The Canvas. A wizard declares the grid; Rust tiles it.
**Reframed 2026-08-05 (Orel).** This was "splits, driven by keybinds". It is now
**wizard-driven**: you pick a workspace, pick a grid, and assign an agent per cell. Splits still
exist underneath - the tiling arithmetic is identical - but the layout's ENTRY POINT is a
document, not a chord.

**Reverses a deliberate refusal.** `APP-BACKLOG-2026.md` S7 records: *"Splits and tabs: REFUSED
for now (Orel, 2026-07-29) ... Revisit only if real daily use produces the sentence 'I need
these two side by side' - and then as a deliberate decision, not a drift."* That refusal was
correct for a single-user terminal. A fleet controller is N-up by definition: you cannot direct
four agents you cannot see. Resolved yes, 2026-08-04.

**The competitor's shape, measured from their shipped bundle 2026-08-05** (carved assets, not
marketing): BridgeSpace calls this **BridgeCanvas**. Its wizard is three steps - `Start` ->
`Layout` (hint *"Choose terminal grid"*) -> `Agents` (*"Next: Add AI agents"*) - over a "Canvas
setup progress" bar. The model is `grid.rows` x `grid.cols` plus a `terminalCount`; each cell
carries `{cwd, agentId}`; the flow is events (`canvas-configured`, `canvas-cancel`,
`canvas-new-terminal`, `CanvasAgentLaunch`) with two failure logs for terminal-create and
agent-launch. States seen: *Single terminal*, *N terminals*, *All terminals filled*, *Show N more
agents*, *Fit all terminals*.

**Why that is good news rather than bad.** Every element of it is a DOCUMENT - steps, a grid
picker, a preview, dropdowns, counters, an empty state. None of it requires a terminal in a
webview. Their xterm.js appears only INSIDE a finished cell, which is exactly where their freeze
class lives. So the wizard is copied in spirit and the engine stays ours: **the seam their
architecture splits on is the seam ours already has.**

**Ours goes one further: two canvases at once**, each bound to its own worktree, because the
whole point of worktrees is comparing two lines of work. Their vocabulary has one canvas.

**The spec is the contract.** The webview emits, and never renders, this:
```ts
{ workspaces: [ { worktree: string, grid: {rows: number, cols: number},
                  cells: [{ cwd: string, agent: string | null }] } ] }
```
Parsed at the boundary, never cast (`chrome/src/protocol.ts` is already this discipline). Pane
count stays a Rust-side fact; the webview names a shape, it does not own one.

**Checkpoint.**
- The spec round-trips: a wizard-declared 2x2 produces four live sessions, and a malformed spec
  is REFUSED at the boundary rather than half-applied.
- `present_all`: one swapchain acquire, N blits, one present. N presents per frame is tearing,
  not tiling - and it is the first thing to build, because every pane feature sits on it.
- EXACT TILING holds for a tree, not just two regions: every leaf's rect sums to the content
  area, no overlap, no gap, at any window size. Assertable without NSViews, as `ChromeLayout`
  already is.
- The mutant: a leaf sized by a constant instead of a remainder must fail the narrow-window case.
  (The 2-region version of this mutant is already in the suite and is known to fire.)
- Each leaf's pty is resized from its own rect. A pane that keeps full width draws *under* its
  neighbour and looks normal - that is the silent failure this checkpoint exists to catch.

### B4 - Agent sessions.
**Goal.** Launch a coding-agent CLI into a pane, verified.
**Input.** The registry recovered in
`Studio/docs/research/bridgespace-teardown/05-agent-cli-registry.md`: `commandCandidates`
probing (cache 5 min hit / 10 s miss), `promptStrategy` (`inline-arg` vs `type-after-launch`),
launch templates, resume templates, per-agent spawn grace and idle windows.
**Checkpoint.**
- Each installed CLI launches into a pane and is verified by banner sniff **or** child-process
  presence, with 3 retries at exponential backoff, seen firing.
- **The dangerous-flag guard**, both directions: auto-approve flags (`--yolo`,
  `--dangerously-skip-permissions`, `--full-auto`, `-a never`, ...) are never auto-typed on the
  user's behalf; the guard must be seen refusing one, and seen staying quiet for a safe flag.
- Stop sequence: `Ctrl-C`, wait, live-child check, second `Ctrl-C`, wait, destroy. Never destroy
  first. Seen on a real agent.

### B5 - Agent state, from the grid.
**Goal.** Know what every agent is doing, without scraping bytes.
**Three sensors, fused, in priority order:** agent CLI hooks (authoritative, e.g. Claude Code's
`SessionStart`) -> the typed grid (`rowText(semantic:)`, OSC 133 zones, alternate-screen flag)
-> child-process poll (fallback only).
**Checkpoint.** One discriminating test per transition, headless, because the core is a
deterministic state machine:
- has child + silent past `inactivityIdleMs` -> idle
- no child + running -> idle
- no child + spawning past grace -> idle
- exit 0 -> done, non-zero -> error
- **and the control**: a mutant that reports state from raw bytes must fail a case the grid
  gets right (a prompt drawn inside an alternate screen).
**Why this slice matters more than it looks.** Everything after it depends on "is this agent
idle" being true rather than approximately true.

### B6 - The context governor. The reason for the project.
**Goal.** The session does not end.
**Two thresholds, not one (Orel, 2026-08-05).** The context window is only half of what runs
out; the SUBSCRIPTION is the other half, and hitting that one mid-task is worse because it does
not compact, it stops. Both are already readable on this machine and both are already read by
`Studio/macos/ai-moach`, so neither needs inventing:
- **Context**: the transcript tail (`TranscriptReader.swift`) - real token counts, window
  inferred from the model family.
- **Quota**: the harness rate-limit state file (`QuotaReader.swift`), verified present
  2026-08-05 with fields `fivePct`, `sevenPct`, `fiveResets`, `sevenResets`, `model`, `ts` - the
  5-hour and 7-day windows as percentages, plus when they reset.
Policy: compact at the CONTEXT threshold; at the QUOTA threshold do not compact - that spends
more quota - but park the pane with its capsule written, show the reset time, and resume when the
window rolls. A governor that keeps compacting into an exhausted quota is a loop that burns the
thing it is trying to protect.

**Mechanism.** Read true token usage from the agent's own transcript tail
(`input_tokens + cache_creation_input_tokens + cache_read_input_tokens`, window inferred from
model family) - the logic already exists and works in `Studio/macos/ai-moach`
(`TranscriptReader.swift`), port it. At the configured threshold: request a capsule in the
shape of the context-flush capsule, write `/clear` into the pty **we own**,
paste the capsule, continue. No tmux, no accessibility hacks, no synthetic events.
**Checkpoint.**
- A real session driven past the threshold, flushed, and continued, with the work surviving:
  the post-flush agent must correctly answer a question that only the pre-flush context knew.
  That is the oracle. "It didn't crash" is not.
- The negative: below threshold, nothing fires. A governor that cannot be shown to stay quiet
  is indistinguishable from one that never runs (SCAR-004).
- Idempotence: a flush that fails mid-way leaves a resumable session, never a half-cleared one.
**Prior art, honestly.** Single-session handoff at the compact boundary is a crowded space
(`who96/claude-code-context-handoff`, `REMvisual/claude-handoff`, and others), and there are
open Anthropic feature requests for a percentage trigger. What does not exist is
**threshold-driven, fleet-wide, cross-agent**, driven by something that owns the pty.

### B7 - Linux and Windows.
**Goal.** The thing other people can actually run.
**Checkpoint.** Build, launch, spawn an agent, present a frame, and pass the smokes on each OS.
Signed/notarised macOS artifacts, plus the release motor sequence
(the release law in CHANGELOG.md): annotated `vX.Y.Z`, `gh release create --verify-tag`,
target-triple artifact names, `SHA256SUMS`.
**Risk.** HIGHEST for stability. `wgpu` on Wayland/X11 next to webkitgtk is the least-tested
combination in this stack, and "fewer crashes" is the stated goal. Budget real time here or ship
macOS-first and say so out loud.

### B8 - Swarm, memory, MCP.
**Goal.** The multi-agent layer, once single agents are boring.
**Input.** `Studio/docs/research/bridgespace-teardown/04-swarm-orchestration.md` - board, two
PATH shims, mailbox, nudge-on-idle, and the governors. **Worktrees already enforce file
ownership better than BridgeSpace's prompt rules**, so that half is done.
**Non-negotiable from day one:** wake suppression after N nudges without task progress, respawn
suppression, and the three-step stuck ladder. Without them an overnight swarm burns quota in a
loop. Memory and MCP management are document panels, which S6's bridge already supports.
**Absorbs** existing `S9 - Automations + MCP control`.

### B9 - Chat mode. The same agents, without a terminal.
**Added 2026-08-05 (Orel):** *"they got Chat as well, for if you're tired of terminals over and
over."* Correct, and it is not a second product - it is a second VIEW of the sessions B4 already
owns. A terminal is a wonderful instrument and a terrible reading surface: to know what four
agents concluded you should not have to read four scrollbacks.

**Why we can build this and a terminal renter cannot do it well.** The transcript does not come
from scraping bytes. It comes from the typed grid B5 already reads: OSC 133 marks every prompt,
input and output region, so `rowText(row, semantic:)` yields *turns* - what was asked, what the
agent answered - as structured data. Everyone renting xterm.js has to regex ANSI out of a byte
stream to get the same thing, which is why nobody does it well.

**The one hard rule:** chat is a VIEW, never a second channel. A message typed in chat is written
into the pty we own, exactly as if typed in the pane; the reply is read back off the grid. No
side-channel to the agent's API, no second history to reconcile - the terminal remains the single
source of truth, and the chat pane cannot drift from it because it has nothing of its own.

**Checkpoint.**
- Turns extracted from the grid match the pane, verbatim, for a real agent session.
- A message sent from chat appears in the pane and its answer appears in both.
- The control: with OSC 133 absent (an unintegrated shell), chat reports "no structured turns"
  rather than inventing them from raw text.

## 4b. Running order (numbers are identity, order is a decision)

Slice numbers never change - a renumber is how a stale queue makes a session rebuild a shipped
feature. The ORDER of work, as of 2026-08-05:

**B3 Canvas -> B4 agent sessions -> B5 agent state -> B6 governor -> B9 chat -> B8 swarm ->
B7 Linux/Windows -> ship.**

Rationale: B6 is the wedge and needs B5's "is it idle" to be true rather than approximate. Chat
(B9) lands before swarm (B8) because it is a view over machinery that already exists, whereas
swarm adds machinery. Platform (B7) is last because it is the highest-risk slice and nothing else
depends on it.

## 6. What we deliberately do not build

Accounts, subscriptions, entitlement checks, credits. A hosted MCP server. Telemetry by
default. Roughly a third of BridgeSpace's releases exist to fix an online entitlement check
locking paying users out of the app they paid for. Local-first deletes that entire failure class.
