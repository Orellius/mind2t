# Canvas slice C1 - the session map

> Written 2026-08-08 for Orel, at the fold where ColuanOS paused. Paste the
> fenced block below into a mind2t session opened in this repo. It is scoped
> to ONE slice on purpose: he has 50,400 lines here already and does not need
> a rewrite, he needs to stop losing sessions.

## The pain, in his own words

> "I need something that will make me less reliant on 7,000 Ghostty windows."
> "I will stop fighting the firewall and losing tracks of what session is what."

Measured the same day: **41 concurrent sibling Claude sessions in one 20-minute
window.** That is the wound. A pretty canvas that does not answer "which one is
this and what is it doing" fixes nothing.

## What C1 is, and what it is not

**IS**: one zoomable surface where every live agent session is a CARD carrying
its own identity - repo, worktree/branch, agent CLI, what it was asked to do,
whether it is waiting on him. Cards are the terminals that already exist; the
canvas is a layout over `Frame::viewport_rows`, not a new terminal.

**IS NOT**: new agent machinery, a manager agent, voice, remote canvases, or a
governance layer. Those are C2+. Adding them here is how a one-week slice
becomes a month.

WHAT TO BUILD, in this order, committing at each verified seam:

1. SESSION IDENTITY as a first-class type, before any UI. Every pane already
   has a pty and a cwd; give it a record: repo name, git branch or worktree,
   which agent CLI is running, the task text it was started with, and a
   state - working / waiting-on-human / idle / exited. Derive what you can
   from ground truth (cwd, `git rev-parse --abbrev-ref HEAD`, the child's
   argv) rather than from anything the operator has to type twice.

2. WAITING-ON-HUMAN IS THE LOAD-BEARING STATE. A session that has asked a
   question and is sitting unread is the actual cost of 41 windows. Detect it
   from the pty stream (a prompt with no output for N seconds, or a known
   agent-CLI question marker) and make it the single most visible thing on
   the surface. If only one feature of this slice works, make it this one.

3. THE CANVAS: a zoomable, pannable surface where each session is a card
   rendering its live terminal. Reuse the existing renderer - a card is a
   viewport, not a new terminal. Zoomed out, a card shows identity and state
   and does NOT need to render every cell; zoomed in, it is the terminal you
   already have, fully interactive.

4. ONE OMNIBOX, keyboard-first: jump to a session by repo/branch/task text,
   and start a new one ("open <repo>", "rename <session>"). No natural-language
   agent behind it in C1 - a fuzzy matcher over the identity records. The
   manager agent is C2 and must not be smuggled in here.

## Why this and not the ColuanOS canvas

ColuanOS's app is four days old and its guest has no filesystem or network.
mind2t is 50,400 lines, 12 crates, and already his daily driver. The canvas is
a surface need; mind2t is the engine that already renders terminals and manages
worktrees. Putting the surface on the newer, thinner foundation would mean
rebuilding the engine to get the view.

ColuanOS stays paused. Its guardrail - capabilities, the hash-chained tape -
is worth adopting into mind2t LATER as an optional "governed run" mode, which
is a far smaller job than finishing an operating system.
